Silencer client reference

Internal Data Contracts

This explainer focuses on the C++ Silencer client application: the main in-process data domains, who owns them, how another client subsystem should read them, and which mutation path is allowed to change them. Server and admin APIs appear only where they form a client edge.

Summary Graph Owner Map Client Data Mutations External Edges Consumer Guide Sources

Summary

Inside the client, Game coordinates lifecycle and the frame loop; World owns simulation state; the current AUTHORITY World is the writer for replicated match state; and specialized subsystems own their own slice of data. New consumers should go through the owner instead of reading or mutating incidental fields in neighboring code.

Coordination

Game owns process state, frame cadence, SDL/TUI input collection, rendering orchestration, session transitions, and local automation queues.

Simulation

World owns map, resources, lobby client, trigger graph, active game mode, object registry, peer registry, network transport, and replication. It borrows the Audio singleton for playback hooks.

Authority

The authority simulates objects and sends snapshots. Replicas send input/intents, load snapshots, and client-predict only their local controlled objects.

Ownership Graph

The graph below shows containment and responsibility, not every call site. A child node is owned/stored by its parent unless the label says it is an adapter, projection, or external source.

External Edges

Go lobby server Owns persisted accounts, progression, game rows, presence, characters. Client Lobby caches replies and pushes.
Game UDP peers WorldNetwork dispatches packets; WorldReplication owns snapshots and input queues.
Community map HTTP mapfetch transfers map files; loaded runtime state belongs to World::map.
Dedicated heartbeat DedicatedServer summarizes an authority world to the lobby; it does not own match truth.
Automation sockets ControlServer and InputServer enter through Game::Loop().
Audio singleton World stores an Audio&; message/network paths trigger playback but do not persist audio state.

Owner Map

Data / Concern Owner Read / Retrieval API Command / Mutation API Boundary
Top-level app state and frame lifecycle Game, especially Game::Loop(). Game::GetState(), StateName(), GetFrameCount(), and high-level accessors such as GetWorld(), GetRenderer(), and GetWorldSummary(). Game::Loop() drains control commands, runs network and simulation ticks, folds input into world.localinput, renders, and posts automation replies. Game coordinates. It should not own simulation data just because the frame loop touches it.
Join, spectate, leave, map load/unload, match summary GameSession. Read session-backed state through Game accessors such as GetWorldSummary(), current World/Lobby state, and the current Game state. Game::JoinGame(), SpectateGame(), and LeaveJoinedGame() delegate to GameSession. GameSession reads LobbyGame map/host fields to set World::mapname, the authority peer endpoint, replica connect flow, map load/unload, object/game-mode reset, and final stats. Host-created lobby UI currently seeds World::gameinfo through LobbyScreen::SeedHostGameInfo() before delegating to JoinGame(). Keep session transitions here. Do not split map teardown or authority reset logic across screens or random tick handlers.
Simulation container and subsystem composition World. Use World public methods and public subsystem members: world.objects, world.network, world.peers, world.replication, world.map, world.resources, world.lobby, world.messaging, and world.triggerGraph. Replay is stored inside World, but is private and should stay on existing owner/friend paths unless a narrow accessor is needed. World::Tick(), TickObjects(), and the owning subsystem methods advance state. Add behavior to the owning subsystem. Avoid reaching through World to mutate private state from unrelated code.
Match lifecycle, lobby game config, shared start state, active mode Game, GameSession, and World. Use Game::GetState()/StateName() for the app-level screen state and Game::GetWorldSummary() for automation-level map/peer/message summary. Existing in-process match code reads World::gameplaystate, gameinfo, and gameMode through the owning GameSession or World code paths. The sharedstate handle itself belongs to Game. Replicas load World::gameinfo from MSG_GAMEINFO. Host-created lobby UI currently seeds World::gameinfo from LobbyGame through LobbyScreen::SeedHostGameInfo(). Game::Loop() drives the shared State gate through Game::sharedstate; session and tick code switch World::gameplaystate, create gameMode from gameinfo.modeId, and set winningteamid/matchEndCalled. This is lifecycle/config state, not the scoreboard projection. If a new non-friend subsystem needs raw lifecycle fields, add a narrow accessor on the owner instead of using GameStateObject as a catch-all.
Object lifetime, lookup, collision indices WorldObjectRegistry, surfaced through world.objects. GetObjectFromId(), GetObjectsByType(), TestAABB(), and TestIncr(). Creation goes through World::CreateObject() and ObjectTypes, then registers all parallel indices. Destruction is two-phase: MarkDestroyObject(), then DestroyMarkedObjects(). Never push/erase objectlist, tobjectlist, objectsbytype, or objectidlookup directly.
Replicated match summary: mode, phase, elapsed time, winner, scores GameStateObject, owned by the authority world and replicated as an object. Read the ObjectTypes::GAMESTATEOBJ instance from the current World object set, then read modeId, matchPhase, matchTimeSecs, winningTeamId, and score[]. Authority creates the object once after World::gameplaystate == INGAME. Its Tick() copies authority world/game-mode state into replicated summary fields; replicas receive it through normal snapshot loading. Use this for scoreboard/display summary. Do not use it for pre-match lobby config, map download readiness, shared-state gating, or session teardown.
Object fields and replicated object serialization Each Object subclass and its mixins. Get objects by ID/type from WorldObjectRegistry, then read through the concrete object type or shared mixin state when that caller already has a legitimate simulation context. Authority ticks objects and writes snapshots through Object::Serialize(). Replicas read snapshots into objects through WorldReplication::LoadSnapshot(). New replicated fields belong in the owning object Serialize(). Replicas must not treat deserialized state as locally authoritative.
Authority/replica mode and UDP transport WorldNetwork, surfaced through world.network. IsAuthority(), IsConnected(), IsIdle(), IsLocalObserver(), GetPingTime(), AveragePingJitter(), and network byte counters. World::Listen()/Bind() bind UDP and enter authority mode. Connect() enters replica mode and sends MSG_CONNECT. Disconnect() clears connection state. DoNetwork() dispatches World::MSG_* packets. The authority applies gameplay mutations. Replicas send input and consume snapshots.
Peers, teams, readiness, observers, parked rejoin slots WorldPeerRegistry, surfaced through world.peers. GetPeer(), GetAuthorityPeer(), GetLocalPeerId(), GetPeerPlayer(), and GetPeerTeam(). Authority MSG_CONNECT adds/rebinds peers. FindTeamForPeer() assigns team membership and may create a TEAM object. SendPeerList() and ReadPeerList() replicate peer summaries. Disconnect either parks a mid-game player for rejoin or removes the peer. Peer IDs, controlled object lists, readiness, team assignment, observer state, and parking semantics stay in the peer registry.
Snapshot replication and input queues WorldReplication, surfaced through world.replication. Most consumers should read the resulting World objects. Diagnostics may read replication counters and queue sizes from world.replication. Replicas send MSG_INPUT. Authority queues and processes peer input, then sends MSG_SNAPSHOT. Replicas sort/load snapshot queues and client-predict the local controlled object path. Snapshot code owns delta compression, old-snapshot rings, and load/save mechanics. Do not duplicate snapshot parsing elsewhere.
Local input state GameInput, InputServer, and world.localinput. Read keymap/gamepad state through Game accessors. Simulation code reads Input via peers or world.localinput, not raw SDL events. SDL and TUI snapshots are normalized in Game::Loop(). Replicas serialize the current local input into MSG_INPUT; authority applies local input directly. Raw SDL event handling stays at the game boundary. Simulation consumes normalized Input.
Messages, chat, status lines, top message, networked sounds WorldMessaging, surfaced through world.messaging and World wrappers. World::GetMessageText(), GetMessageProgress(), GetMessageType(), GetMessageTime(), GetTopMessageText(), and GetTopMessageProgress(). Current HUD/render paths also read world.messaging.chatlines and statusmessages. ShowMessage(), ShowStatus(), ShowTopMessage(), SendChat(), and SendSound(). Network handlers for MSG_CHAT, MSG_STATUS, and MSG_MESSAGE enter through WorldNetwork and delegate here. Inbound MSG_SOUND is handled directly by WorldNetwork resolving sound assets and playing through Audio. Messaging is presentation-facing world state, but it is still world-owned state. Do not store a second chat/status model in a screen or renderer.
Trigger graph definitions, runtime events, authority action scheduling TriggerGraph and its internal ActionSystem, owned by World. IsObjectiveComplete(), GetFlag(), Objectives(), and diagnostic dirty-state helpers. Map::Load() loads trigger nodes/zones into TriggerGraph. Authority TriggerGraph::Tick() evaluates pending events, zone/timer events, schedules actions, completes objectives, and sets flags/enabled state. Runtime event producers emit GameEvents through triggerGraph.Bus().Emit(). Pending events, elapsed timers, zone occupancy, and queued actions are authority-local runtime state. They are not serialized for replicas.
Replicated trigger projection TriggerGraph::SerializeState() / ApplySerializedState(). Replicas read objective completion with IsObjectiveComplete(), flags with GetFlag(), and objective definitions with Objectives() after applying trigger state. Authority calls World::BroadcastTriggerState(), which sends MSG_TRIGGER_STATE containing objective completion, node enabled/fired flags, hit counts, and flags. Replicas apply that projection with ApplySerializedState(). Action effects propagate through normal object snapshots or explicit message/sound/camera packets, not through replicated action timers.
Lobby client cache: account, characters, games, presence, user info Lobby inside World. GetGameById(), GetUserInfo(), GetSelectedCharacter(), GetSelectedAgencyOrDefault(), games, presence, and changed flags such as presencechanged or charactersreceived. Lobby::DoNetwork() reads lobby TCP frames and updates caches. Send methods such as SendCredentials(), CreateGame(), SendSetGame(), CreateCharacter(), SelectCharacter(), and RegisterStats() request server-side mutations. Client Lobby is a cache/protocol adapter. The Go lobby owns persisted accounts, progression, game rows, and presence truth.
Resources and data-driven content Resources, GASLoader, BehaviorTreeLibrary, SoundCueLibrary. Read loaded sprites, tiles, sounds, actor definitions, GAS, behavior trees, and sound cues from the resource/library owner that loaded them. Resources::Load() loads local asset files from the resource directory. Dedicated servers skip or stub video/audio heavy work where appropriate. Current startup loading is local-filesystem based. HTTP actor/BT fetch helpers exist, but they are not the active startup source.
World view, pan camera, spectator focus, system-camera slots World camera/view fields, read by renderer and UI inset drawing. Read focus through world.viewedpeerid, World::IsLocalObserver(), and system-camera accessors such as IsSystemCameraActive(), GetSystemCameraFollowId(), GetSystemCameraX(), and GetSystemCameraY(). Trigger actions and MSG_CAMERA mutate pan-camera fields; spectator tick code mutates viewedpeerid and spectator; world methods own system-camera slot writes. This is not renderer-owned screen-buffer state. Renderer and UI inset code consume these fields to choose what to draw.
Replay recording/playback Replay inside World. IsRecording(), IsPlaying(), GameStarted(), ShowAllNames(), and replay camera fields for playback rendering. Authority/network paths write game info, peers, user info, input commands, chat, tech, station actions, disconnects, and ticks. Playback reads those records back into World. Current playback/render code also updates replay camera, speed, and display fields from local input/camera follow paths. Replay is a serialized event/state view. Its current camera fields are a legacy render/playback-derived state exception; replay should not become a second live state owner.
Renderer-visible output and screenshots GameRenderer, Renderer, and render subsystems. Use Game::GetScreenBuffer(), GetPaletteColors(), GetRenderer(), and screenshot/control-socket commands for automation reads. The render pipeline consumes World and UI state after simulation/input processing and writes the screen buffer or GPU output. Current renderer code also rewrites derived camera interpolation fields on the local player and rebuilds world.map.minimap.surface from map minimap pixels. Rendering mostly displays state, but these legacy derived-state writes exist today. Do not use them as precedent for renderer ownership of game/lobby data or new simulation mutations.
UI navigation and UI input ClientUi, GameUiPipeline, screens/modals. Game::UiInput(), CurrentUiInput(), UiInteractions(), GetTopScreen(), and HasUiInputTarget(). Screens declare one UI frame; typed UI actions are handled after layout. GameUiPipeline gates SDL text input. PushScreen(), PopScreen(), and ReplaceScreen() mutate the UI stack through Game/ClientUi. UI is usually a command/read surface. Current lobby-connect UI is a boundary leak: LobbyConnectScreen::Tick() locks world.lobby and drives connect/auth Lobby::state transitions. Keep new networking transitions behind Lobby methods instead of expanding screen ownership.
Local automation and test control ControlServer, ControlDispatch, InputServer, clients/cli. Use silencer-cli or the JSON-lines control socket. Prefer command results and screenshots over direct process introspection. Game::Loop() drains immediate, post-render, and multi-frame wait commands. The binary input socket is latest-wins state. This is a local test/agent contract, not a production remote API or gameplay ownership layer.

Client Data Domains

Question Current Contract Where To Look First
What state is the application in? Game owns the app state enum, pending state, frame count, pause/step state, control ports, headless/TUI flags, and top-level screen stack operations. clients/silencer/src/game/game.h, game/loop/game_loop.cpp.
Where is match lifecycle/config state? GameSession owns session commands and teardown, Game/Game::Loop() own the shared-state handle and transition gate, and World owns gameplaystate, gameinfo, active GameMode, and end-of-match fields. Host-created lobby UI has an existing friend-of-World seeding path for World::gameinfo before session join; treat that as a boundary leak, not general UI ownership. GameStateObject is not created until the world is already in INGAME. world.h, game/session/game_session.cpp, game/tick/tick_hostjoin.cpp, game/tick/tick_ingame.cpp, game/loop/game_loop.cpp.
Where is replicated match summary? GameStateObject carries the scoreboard/display projection: game mode id, phase, elapsed seconds, winning team, and team scores. Replicas read it from snapshots like any other replicated object. game/state/gamestateobject.*, world.cpp, world/network/world_replication.cpp.
Where is player state? Account/selected-character data is cached in world.lobby. In-match peer state is in Peer. The live player object is an ObjectTypes::PLAYER entry owned by WorldObjectRegistry. net/lobby.*, net/peer.*, player.*, world/objects/world_objects.cpp.
Where are teams and readiness? WorldPeerRegistry assigns peers to teams and replicates peer summaries. Team objects carry team gameplay state. world/network/world_peer_registry.cpp, game/actor/team.*.
Where are map and content assets? World owns the current Map; Resources::Load() loads local sprites, tiles, sounds, actor defs, behavior trees, GAS, and sound cues from the resource directory. resources/resources.*, world/map/, shared/assets/.
Where are match stats before persistence? Per-peer in-match stats live on Peer::stats. End-of-match code copies stats into User::statscopy and sends Lobby::RegisterStats(). net/peer.h, game/session/game_session.cpp, game/actor/stats.*.
Where are lobby game rows and presence? The client caches lobby server pushes in Lobby::games and Lobby::presence. Those are local views of Go lobby state, not sources of truth. net/lobby.h, net/lobby.cpp, shared/lobby-protocol/protocol.md.
Where are messages, chat, and status text? WorldMessaging owns current message/top-message fields, chat lines, status lines, and networked sound commands. Read through World message getters or add a focused WorldMessaging getter for a new non-render consumer. world/messaging/world_messaging.*, world/network/world_network.cpp, game/loop/game_loop.cpp.
Where are objectives and trigger state? TriggerGraph owns loaded trigger nodes/zones, authority-local pending events, timers, zone occupancy, and action scheduling. MSG_TRIGGER_STATE only replicates objective completion, node enabled/fired flags, hit counts, and flags. events/TriggerGraph.*, events/ActionSystem.h, events/TriggerDef.h, world/messaging/world_messaging.cpp, world/network/world_network.cpp, world/map/map.cpp.

Mutation Paths

The recurring mistake to avoid is mutating a cached or rendered view instead of the owner. The table below names the intended write path.

Mutation Allowed Path Why
Create or destroy an object World::CreateObject() and World::MarkDestroyObject(). Keeps all object lists, type indices, and ID lookup synchronized; avoids invalidating active iteration.
Change match lifecycle/config state GameSession session commands, Game::Loop() transition code, and World tick/state code; host-created lobby UI currently seeds World::gameinfo through LobbyScreen::SeedHostGameInfo(). Game::Loop() drives the shared State gate through Game::sharedstate, while map/session ticks update World::gameplaystate, gameMode, and match-end fields. Those fields coordinate connection, map download, peer readiness, active mode, and teardown. Changing them outside the session/tick owners breaks the match state machine.
Change live gameplay state Authority-side object/game-mode/world subsystem code, usually through a World::MSG_* intent from replicas. Only authority state is replicated. Replica-only writes are overwritten or desync-prone.
Send player input GameInput/InputServer to world.localinput, then WorldReplication::SendInput() for replicas. Keeps SDL/TUI/keymap handling outside simulation and preserves the existing input protocol.
Change team, ready state, tech, or station action Replica sends the corresponding World::MSG_*; authority handles it in WorldNetwork::DoNetwork_Authority(). Peer/team/gameplay choices must be validated by the authority before other clients see them.
Join, spectate, leave a lobby-spawned match GameSession via Game::JoinGame(), SpectateGame(), or LeaveJoinedGame(). Session code keeps map, authority peer, world mode, lobby channel, and teardown state together.
Show message, chat, status, top message, or networked sound WorldMessaging methods, usually through World wrappers or WorldNetwork packet handlers. Keeps transient presentation state, network fan-out, chat formatting, and local playback in one owner.
Change objective or trigger state Authority TriggerGraph methods/actions, fed by GameEvents and replicated with World::BroadcastTriggerState(). Trigger truth is authority-owned; replicas should apply MSG_TRIGGER_STATE instead of evaluating objectives locally.
Update lobby account/character/progression state Lobby send methods over lobby TCP: auth, create/select character, upgrade stat, register stats. The Go lobby owns persistence; the C++ client cache updates from server replies/pushes.
Load or change runtime content Resource/library loaders for local assets; admin/editor workflows must still ship files through the asset package. The current client startup path reads local resources. HTTP editor APIs are not the active runtime source.
Record or replay match data Replay write/read methods called from existing network/session paths, plus current render/playback camera field writes. Replay follows world/network events. Existing camera/display writes are derived-state exceptions, not a general bypass around the world mutation model.
Drive automated tests silencer-cli through control/input sockets. Automation uses the same frame loop and command dispatch as runtime verification.

External Client Edges

Edge Client Owner Contract Internal Boundary
Lobby TCP Lobby. [len u8][opcode u8][payload] frames for version, auth, MOTD, chat, game rows, user info, stats, presence, and characters. Lobby converts wire pushes into local caches. Other code should not parse lobby frames.
Game UDP WorldNetwork and WorldReplication. World::MSG_* datagrams for connect, snapshots, input, peer list, game info, map transfer, chat, gameplay intents, kicks, trigger state, and camera. Transport dispatch stays in WorldNetwork; snapshot mechanics stay in WorldReplication.
Dedicated-server lobby heartbeat DedicatedServer. UDP heartbeat to lobby with game id, bound port, state, parked account IDs, tick count, and alive mask. Heartbeat summarizes a running authority. It does not define match state inside the client.
Map HTTP mapfetch helpers and map/session flows. GET /api/maps, GET /api/maps/by-sha1/:sha1, and POST /api/maps for community maps. HTTP map transfer is an asset edge; loaded map state belongs to World::map.
Local control/input sockets ControlServer, ControlDispatch, InputServer. JSON-lines commands and binary input snapshots used by clients/cli and tests. Commands enter through Game::Loop() phases so automation observes the real frame lifecycle.

Consumer Guide

If You Need... Use... Avoid...
Match lifecycle/config or map/lobby game details Game/GameSession/World owner paths, existing Game::GetWorldSummary() for automation summary, or a new narrow owner accessor if the raw field is currently private. Using GameStateObject as a substitute for lobby config, map readiness, shared-state gates, or teardown state.
Current scoreboard phase, score, elapsed time, or winner GameStateObject read from the current World object set after match start. Inventing a second scoreboard model in UI/render code, or reading it before gameplaystate == INGAME.
A player object for a peer World::GetPeerPlayer(peerid). Scanning object lists in every caller.
An account name or selected character details world.lobby.GetUserInfo(accountid) and character helpers. Assuming peer/account IDs contain display metadata.
Current message, chat, or status text World message getters or a focused WorldMessaging getter for chat/status collections. Mirroring transient message queues in a screen, renderer, or control command.
Objective completion or trigger flags world.triggerGraph.IsObjectiveComplete(), GetFlag(), or Objectives(). Treat pending events/action scheduling as authority-local. Having replicas infer objective truth from local events or expecting action timers to be replicated trigger data.
To add a replicated gameplay field The owning object or peer serialization path, plus protocol/version review. Side-channel globals or renderer-only state.
To observe live world state externally A compatible spectator/game peer over UDP, or a new authority-owned read API. Using admin/session summaries as if they were object snapshots.
To test or inspect the running client silencer-cli, control socket commands, screenshots, and input snapshots. Adding production-only hooks for test visibility.
