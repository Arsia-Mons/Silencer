## Codebase Patterns

(Inherited from the first-milestone Ralph run via git history — these
remain true and load-bearing. New patterns from this run get appended
below.)

- **Bridge → Surface dispatch contract** lives in
  `clients/silencer/src/ui/clay/clay_bridge.{h,cpp}`. RECTANGLE/BORDER
  color = `backgroundColor.r` as palette index (Uint8). IMAGE
  `imageData` = `PackImage(bank, idx)`. TEXT `fontId` = bank,
  `fontSize` = cell width. CUSTOM `customData` = `ClayCustomData*` with
  a `CustomKind` enum. Scissor stack in `g_clipStack`.
- **Clay determinism**: `EnsureInitialized` in clay_bridge.cpp resets
  pointer state / scroll containers / measure cache unconditionally
  before each `Clay_BeginLayout`. Downstream callers get this free.
- **Sprite anchor offsets**: a sprite blitted at `boundingBox.{x,y}`
  lands at `(x + spriteoffsetx[bank][idx], y + spriteoffsety[bank][idx])`
  on Surface. Lobby Clay tree pre-subtracts those offsets in the
  floating `.offset` to make the on-screen pixels land where Clay says.
  When the chrome moves from `floating @ ROOT (x, y)` to flex layout,
  these offsets generally aren't needed (Clay's bounding box becomes
  the on-screen pixel coord directly) — but watch for them anywhere
  sprites are emitted.
- **Clay primitives live at** `clients/silencer/src/ui/clay/primitives/<name>.{h,cpp}`
  in `namespace silencer::ui::primitives`. They include `clay_bridge.h`
  but NEVER `world.h` / `lobby.h` / `config.h` / `MapDownloader`.
  Variants are explicit enums (not strings). Per-frame userData
  payloads come from fixed-capacity bump arenas owned by the primitive
  TU; caller invokes `<Primitive>BeginFrame()` before `Clay_BeginLayout`.
- **De-lobby primitive defaults pattern** — reference commit `63c779d`.
  When a primitive's default value encodes lobby visual identity, drop
  the default so the caller must spell it explicitly. Screen-scope
  callers add a file-scope `constexpr` for the value; tests/demos use
  inline literals with `/*paramName=*/` comments. Header docstrings
  stop claiming the legacy value is canonical.
- **Atomic commit + flag flip invariant** — the iteration's
  implementation changes and the `prd.json` `passes` flip from
  `false→true` MUST land in the SAME commit. Stage implementation
  paths, run jq to flip the flag, stage `prd.json` + `progress.txt`,
  commit. If the commit fails (hook etc.), DO NOT flip the flag in a
  separate commit.
- **Adding a Clay-scene control op for a primitive test** — 3 changes:
  declare in clay_bridge.h, implement in `clients/silencer/src/ui/clay/<name>_test.cpp`
  (mirror clay_smoke.cpp), wire the op in `controldispatch.cpp`'s
  HandleImmediate switch. NEW .cpp files require
  `cmake -B build -S clients/silencer` to refresh GLOB_RECURSE.
- **Test infra at** `tests/lobby-clay/<name>_test/run.sh` follows a
  standard pattern: start binary, run control op, pixdiff against
  reference. The `SILENCER_BIN` env var lets you override the
  binary path when the harness's auto-detection picks a stale build.
- **The 40_lobby_clay_basic.sh e2e** drives the full lobby through Clay
  via `cli click --label` and `cli set_text --label`. Use it as the
  functional regression gate — if it stays green, you haven't broken
  user-visible flows.
- **Primitives with a caller-supplied id**: `.id` on a
  `Clay_ElementDeclaration` is a `Clay_ElementId`, not a `Clay_String`.
  When the primitive takes the id as a `Clay_String` parameter, convert
  with `Clay_GetElementId(s)` before assigning to `.id`. `CLAY_ID(literal)`
  only works on string literals at the call site.
- **Per-element opacity** rides on `backgroundColor.a` (0..255). Clay
  gates RECTANGLE emit on `a > 0`, so `a == 0` doubles as the "no fill"
  sentinel. Alpha values 1..254 are honored by the bridge via the
  palette alphaed LUT (one-cut: quantized to ≈50%). 255 stays on the
  fast `DrawFilledRectangle` path.
- **Palette alphaed LUT** at `palette.cpp` `Calculate`. `alphaed[i*256+j]`
  blends src palette index `i` over dst palette index `j` at an alpha
  encoded by `i`'s low nibble: `((i-2)%16)/16`. Levels > 0.5 collapse to
  fully opaque, so usable intermediate alphas are 0..8/16 → 0..50%. The
  LUT is ONLY populated for src/dst in `[2, 226)` — entries with src or
  dst at 0/1 or in the parallax band [226, 256) read back as 0
  (memset-zero from Load). Translucent rects over a palette-0
  background therefore render as 0; smoke tests must use a non-zero
  backdrop to see the blue/red blend.
- **Translucent RECTANGLE perf**: the bridge takes a per-pixel
  GetPixel→LUT→SetPixel path when opacity < 255. For chrome-scale
  panels (lobby rectangles ~200x400) this is cheap; don't reach for
  this on full-screen overlays without measuring.
- **Canonical container primitive is named Box, not Rectangle.**
  `silencer::ui::primitives::Box(...)` lives at
  `clients/silencer/src/ui/clay/primitives/box.{h,cpp}`. The test scene
  is `RunBoxTest` at `box_test.cpp`, control op `clay_box_test`, test
  harness `tests/lobby-clay/box_test/`. The word "rectangle" still
  appears where it refers to the geometric shape on screen or to the
  Clay bridge's RECTANGLE render command — that's about the rendered
  primitive, not the API name. Future siblings (Row, Column, Stack)
  follow Box's role-neutral naming convention.
- **Box halo stroke routes through `CustomKind::BoxStroke`** when
  any halo width > 0. Otherwise the no-halo path emits the stroke via
  Clay's native `.border` (cheap). The CUSTOM dispatch in the bridge
  draws concentric inset rings — outer halo bands first, primary
  stroke next, inner halo bands last — each ring's thickness equal to
  its `<thing>HaloWidth` param. Total stroke thickness (and effective
  content inset) = outerHaloWidth + strokeWidth + innerHaloWidth.
  Lobby-canonical halo palette: primary 216, outer 75 (1 px), inner 77
  (1 px). C2 finalizes per-rectangle picks.
- **`BoxBeginFrame()` arena reset is REQUIRED for halo callers** but
  optional for no-halo callers — the no-halo path skips the arena
  entirely (Clay's `.border` carries everything). Pattern: scene calls
  `BoxBeginFrame()` once before `Clay_BeginLayout()`, then any number
  of Box() calls with non-zero halos.
- **Headless test scenes default to startup palette 0** — palette
  block 2 (the lobby palette) is NOT auto-loaded by control-op
  rendering. Test scenes that visually mimic the lobby chrome must
  call `game.GetRenderer().palette.SetPalette(2)` BEFORE `Render(...)`
  and restore to `SetPalette(0)` after (so subsequent control ops in
  the same daemon session see their expected colors). Without this,
  idx 216 reads as red instead of the lobby's bright green, idx
  75/77 as muted off-tones instead of dark greens — palette-shifted
  output that doesn't match the legacy BG art.
- **Visual stroke rect ≠ panel interface rect.** A legacy `*_panel.cpp`
  file declares an `Interface` rect (e.g. chat panel at
  (15, 216, 368, 234)) but the actual visible chrome stroke rectangle
  in the BG sprite is offset OUTWARD — chat-box stroke is at
  (10, 195, 378, 260). Stroke is 5 px outset on left/right/bottom and
  21 px outset on top (the top extra is the channel-header band).
  When pulling chrome coords from legacy panel `Interface` decls,
  always cross-check by scanning the BG decoder output for the
  primary stroke (idx 216) runs at the expected axes — the panel
  interior coords WILL be wrong.
- **Cross-panel halo anomalies on shared edges.** Where two
  rectangles' chromes touch (e.g. chat-box right edge abutting
  character panel left edge), the halo palette indices at offsets
  ±1 from the primary stroke differ from the rectangle's "clean"
  edges. The canonical halo pick is the clean-edge sampling, not
  the abutting-edge sampling. Note the anomaly in
  `docs/plans/lobby-chrome-rectangles.md` rather than averaging it
  into the canonical value.

## 2026-05-11T17:30:00Z - C0c Box stroke halos (multi-tone outer + inner rings)

- **Learnings for future iterations:**
  - Concentric-ring drawing: a single Clay CUSTOM render command can
    draw an arbitrary number of nested rect outlines without needing
    extra Clay elements. The bbox is supplied by Clay; the bridge
    iterates the rings in the CUSTOM dispatch. Cleaner than emitting
    one Clay child per ring (which would force separate Clay layout
    decisions for each).
  - When extending a primitive's API with new REQUIRED params, the
    de-lobby-defaults rule (63c779d) means every existing caller has
    to be touched. For Box that meant box_test.cpp (4 callsites),
    rectangle_alpha_test.cpp (3 callsites) — small blast radius
    because C3+ haven't introduced lobby-side callers yet. Doing the
    rename + the halo extension before the lobby integration was the
    right ordering — adding 6 params after lobby relocation would
    have meant 20+ callsites to update.
  - Per-frame arena pattern with optional reset: when only SOME
    callsites need the arena (here: halo-using ones), let the
    BeginFrame() be optional and document the conditional contract in
    the header. No-halo callers (which is everyone in C1 era) get a
    zero-cost path. The arena reset only matters when scenes actually
    use halos in their layout.
  - For sampling palette indices at sub-pixel resolution, the
    `/tmp/inspect_lobby_stroke*.py` scripts decode the source sprite
    bin straight rather than reading the rendered PNG. This is robust
    against any rendering surprises (palette quantization, alpha
    quirks) and is the canonical way to confirm a "what palette index
    is this pixel" question against the legacy art.

    `Clay_String`. To assign a runtime string id, wrap with
