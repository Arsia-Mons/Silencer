## Codebase Patterns

(Inherited from the first-milestone Ralph run via git history — these
remain true and load-bearing. New patterns from this run get appended
below.)

- **Bridge → Surface dispatch contract** lives in
  `clients/silencer/src/ui/clay/clay_bridge.{h,cpp}`. RECTANGLE/BORDER
  color = `backgroundColor.r` as palette index (Uint8). IMAGE
  `imageData` = `PackImage(bank, idx)`. TEXT `fontId` = bank,
  `fontSize` = cell width. CUSTOM `customData` = `ClayCustomData*` with
  a `CustomKind` enum. Scissor stack in `g_clipStack`.
- **Clay determinism**: `EnsureInitialized` in clay_bridge.cpp resets
  pointer state / scroll containers / measure cache unconditionally
  before each `Clay_BeginLayout`. Downstream callers get this free.
- **Sprite anchor offsets**: a sprite blitted at `boundingBox.{x,y}`
  lands at `(x + spriteoffsetx[bank][idx], y + spriteoffsety[bank][idx])`
  on Surface. Lobby Clay tree pre-subtracts those offsets in the
  floating `.offset` to make the on-screen pixels land where Clay says.
  When the chrome moves from `floating @ ROOT (x, y)` to flex layout,
  these offsets generally aren't needed (Clay's bounding box becomes
  the on-screen pixel coord directly) — but watch for them anywhere
  sprites are emitted.
- **Clay primitives live at** `clients/silencer/src/ui/clay/primitives/<name>.{h,cpp}`
  in `namespace silencer::ui::primitives`. They include `clay_bridge.h`
  but NEVER `world.h` / `lobby.h` / `config.h` / `MapDownloader`.
  Variants are explicit enums (not strings). Per-frame userData
  payloads come from fixed-capacity bump arenas owned by the primitive
  TU; caller invokes `<Primitive>BeginFrame()` before `Clay_BeginLayout`.
- **De-lobby primitive defaults pattern** — reference commit `63c779d`.
  When a primitive's default value encodes lobby visual identity, drop
  the default so the caller must spell it explicitly. Screen-scope
  callers add a file-scope `constexpr` for the value; tests/demos use
  inline literals with `/*paramName=*/` comments. Header docstrings
  stop claiming the legacy value is canonical.
- **Atomic commit + flag flip invariant** — the iteration's
  implementation changes and the `prd.json` `passes` flip from
  `false→true` MUST land in the SAME commit. Stage implementation
  paths, run jq to flip the flag, stage `prd.json` + `progress.txt`,
  commit. If the commit fails (hook etc.), DO NOT flip the flag in a
  separate commit.
- **Adding a Clay-scene control op for a primitive test** — 3 changes:
  declare in clay_bridge.h, implement in `clients/silencer/src/ui/clay/<name>_test.cpp`
  (mirror clay_smoke.cpp), wire the op in `controldispatch.cpp`'s
  HandleImmediate switch. NEW .cpp files require
  `cmake -B build -S clients/silencer` to refresh GLOB_RECURSE.
- **Test infra at** `tests/lobby-clay/<name>_test/run.sh` follows a
  standard pattern: start binary, run control op, pixdiff against
  reference. The `SILENCER_BIN` env var lets you override the
  binary path when the harness's auto-detection picks a stale build.
- **The 40_lobby_clay_basic.sh e2e** drives the full lobby through Clay
  via `cli click --label` and `cli set_text --label`. Use it as the
  functional regression gate — if it stays green, you haven't broken
  user-visible flows.
- **Primitives with a caller-supplied id**: `.id` on a
  `Clay_ElementDeclaration` is a `Clay_ElementId`, not a `Clay_String`.
  When the primitive takes the id as a `Clay_String` parameter, convert
  with `Clay_GetElementId(s)` before assigning to `.id`. `CLAY_ID(literal)`
  only works on string literals at the call site.
- **Per-element opacity** rides on `backgroundColor.a` (0..255). Clay
  gates RECTANGLE emit on `a > 0`, so `a == 0` doubles as the "no fill"
  sentinel. Alpha values 1..254 are honored by the bridge via the
  palette alphaed LUT (one-cut: quantized to ≈50%). 255 stays on the
  fast `DrawFilledRectangle` path.
- **Palette alphaed LUT** at `palette.cpp` `Calculate`. `alphaed[i*256+j]`
  blends src palette index `i` over dst palette index `j` at an alpha
  encoded by `i`'s low nibble: `((i-2)%16)/16`. Levels > 0.5 collapse to
  fully opaque, so usable intermediate alphas are 0..8/16 → 0..50%. The
  LUT is ONLY populated for src/dst in `[2, 226)` — entries with src or
  dst at 0/1 or in the parallax band [226, 256) read back as 0
  (memset-zero from Load). Translucent rects over a palette-0
  background therefore render as 0; smoke tests must use a non-zero
  backdrop to see the blue/red blend.
- **Translucent RECTANGLE perf**: the bridge takes a per-pixel
  GetPixel→LUT→SetPixel path when opacity < 255. For chrome-scale
  panels (lobby rectangles ~200x400) this is cheap; don't reach for
  this on full-screen overlays without measuring.

## 2026-05-11T16:35:00Z - C1 Bridge alpha-blended RECTANGLE fills
- The bridge's `DispatchRectangle` now reads `backgroundColor.a`. When
  the alpha is 255, the fast `Renderer::DrawFilledRectangle` path stays
  — byte-identical behavior with C0. When the alpha is 1..254, the
  bridge walks each pixel inside the bbox and writes
  `palette.Alpha(AlphaSrcIndex(color, opacity), dstPixel)`. The signature
  of `DispatchRectangle` now takes a `Renderer&` so it can reach
  `renderer.palette`. The `Render(Resources&, Renderer&, ...)` overload
  threads it through unchanged at the call site.
- `AlphaSrcIndex(color, opacity)` constructs the LUT src index from a
  caller-supplied palette color and the desired alpha. First-cut
  quantization: any non-255 opacity routes to ramp position 8 (≈50%).
  Edge cases — palette indices < 2 or ≥ 256-30 fall back to the input
  color so the LUT's unpopulated regions don't read back as 0 silently;
  callers that need translucency in those bands have to extend the LUT
  first (out of scope for C1).
- New test scene at `clients/silencer/src/ui/clay/rectangle_alpha_test.cpp`:
  full-screen backdrop (palette idx 7) with a fully-opaque red rect
  (idx 164) and a 50%-opaque blue rect (idx 132) overlapping its right
  half. Three regions: pure red on backdrop, red+blue overlap blend,
  pure blue on backdrop. Reference shows the LUT-driven mid-tone in the
  overlap.
- Control op `clay_rectangle_alpha_test` wired in `controldispatch.cpp`
  next to `clay_rectangle_test`. CLI passes through (`cli --port $PORT
  clay_rectangle_alpha_test --out path.png`).
- Test harness at `tests/lobby-clay/rectangle_alpha_test/{run.sh,reference.png}`
  with pass bar < 0.5% pixdiff. Verified at 0.0000%.
- C0 reference.png regenerated — variant 4 (fill-with-opacity over an
  existing-color background) now shows the actual alpha-blended midtone
  instead of the placeholder solid fill from the C0-era bridge. C0 test
  remains green.
- 40_lobby_clay_basic.sh still green — no regression on the lobby flow.
- Files changed: `clay_bridge.{h,cpp}` (alpha path + decl), `primitives/
  rectangle.h` (header docs), new `rectangle_alpha_test.cpp`, new test
  harness, refreshed C0 `reference.png`, `controldispatch.cpp` (new op).
- **Learnings for future iterations:**
  - The palette alphaed LUT's "alpha encoded in src low nibble" scheme
    means there is no single canonical "src palette index" for color C
    at alpha α — you construct it from C's color ramp base + α's level
    index. Document this in any future primitive that needs alpha.
  - `alphaed[i*256+j]` is unpopulated for j in {0, 1} or j ≥ 226. Any
    smoke test for translucent rects MUST use a backdrop palette index
    inside [2, 226) — palette 0 is a black hole.
  - When a primitive's bridge dispatch needs the palette, threading
    `Renderer&` through the dispatch helper is fine — the existing
    Render() entry points already carry it, and the static
    `DrawFilledRectangle` / `GetPixel` / `SetPixel` calls compose
    naturally.

## 2026-05-11T16:22:00Z - C0 Rectangle primitive
- New primitive `silencer::ui::primitives::Rectangle(id, w, h, fillColor,
  fillOpacity, strokeColor, strokeWidth)` at
  `clients/silencer/src/ui/clay/primitives/rectangle.{h,cpp}`. Screen-agnostic
  — no world/lobby/config includes; verified.
- All 7 visual knobs are required POSITIONAL parameters. The compiler refuses
  callers that forget any of them, matching the de-lobby precedent from
  commit 63c779d. No defaults, no opts-struct, no per-variant indirection.
- Sentinels: `fillOpacity == 0` → no fill (Clay skips RECTANGLE since `a > 0`
  gate fails). `strokeWidth == 0` → no border. `width|height == 0` →
  `CLAY_SIZING_GROW(0)` on that axis (use inside flex containers); non-zero
  → `CLAY_SIZING_FIXED`. Intermediate opacity (1..254) is carried on the
  render command's `backgroundColor.a` for the C1 bridge to consume; until
  C1 lands the bridge ignores alpha and renders fully opaque (documented).
- 4-variant test scene at `clients/silencer/src/ui/clay/rectangle_test.cpp`:
  stroke-only, fill-only, fill+stroke, fill-with-opacity over an existing
  background color. Laid out in a 2x2 flex grid (640x480 root, TOP_TO_BOTTOM
  outer + LEFT_TO_RIGHT rows, 30 px childGap). The fourth cell wraps an
  underlying opaque CLAY block (palette idx 96) and emits the translucent
  overlay Rectangle inside it via padding — the parent's
  `.backgroundColor` provides the underlying color so the alpha overlay has
  something to blend with once C1 lands.
- Control op `clay_rectangle_test` wired in `controldispatch.cpp` directly
  before the existing `clay_panel_test` handler. CLI passes the op through
  unchanged (`cli --port $PORT clay_rectangle_test --out path.png`).
- Test harness at `tests/lobby-clay/rectangle_test/{run.sh,reference.png}`.
  Pixdiff = 0.0000% on the verification run after REGEN.
- 40_lobby_clay_basic.sh still green — no regression.
- Files changed: `clay_bridge.h` (forward decl), `controldispatch.cpp` (op
  handler), new `rectangle.{h,cpp}`, new `rectangle_test.cpp`, new test
  harness.
- **Learnings for future iterations:**
  - `.id` on a Clay_ElementDeclaration is a `Clay_ElementId`, not a
    `Clay_String`. To assign a runtime string id, wrap with
    `Clay_GetElementId(string)`. The `CLAY_ID(literal)` macro only accepts a
    string literal — primitives that take a caller-supplied id and pass it
    into the decl MUST go through `Clay_GetElementId`.
  - Clay's RECTANGLE-emit gate is `backgroundColor.a > 0`. Setting alpha to
    the desired opacity (0..255) doubles as both the "no fill" sentinel
    (a==0 suppresses emit entirely) AND the carrier for C1's alpha-blend
    routing — no extra userData struct or CustomKind needed at the C0 API
    layer.
  - For test scenes, screenshot DMs use the rendered PNG directly
    (`/tmp/ralph-shots/iter-<ID>.png`) since there's no lobby state to
    capture yet. The reference.png IS the screenshot.
