## Codebase Patterns

(populated by iterations — one-liners only, learnings the next iteration must not re-derive)
- Clay 0.14 requires C++20 (`__cplusplus >= 202002L`); silencer's CMake bumps `cxx_std_14` → `cxx_std_20`.
- `clay.h` lives at `clients/silencer/third_party/clay/clay.h`; include as `#include "clay/clay.h"` since `third_party/` is on the include path (CMakeLists.txt:118).
- `CLAY_IMPLEMENTATION` is defined in exactly one TU: `clients/silencer/src/ui/clay/clay_init.cpp`. Picked up automatically by the `src/*.cpp` GLOB_RECURSE.
- macOS binary lives at `build/Silencer.app/Contents/MacOS/Silencer`; verify Clay symbols with `nm <bin> | grep _Clay_`.
- `tools/pixdiff` is a standalone CMake project; configure with `cmake -S tools/pixdiff -B tools/pixdiff/build`, build with `cmake --build tools/pixdiff/build -j`. Binary at `tools/pixdiff/build/pixdiff`. Sibling target `gen_fixtures <dir>` regenerates the 16x16 test PNGs.
- `stb_image.h` lives at `tools/pixdiff/stb_image.h` (v2.30, fetched from nothings/stb master). Do not copy it elsewhere — if another tool needs it, point its include path at `tools/pixdiff/`.
- pixdiff metric is byte-level equality count over the RGBA buffer (mismatched pixels weighted equally regardless of distance). Same-size mismatched dims short-circuit to 100.0.
- The lobby renders panels in CHILD interfaces nested under the screen's top-level iface. `cli inspect`/`click --label`/`set_text --uid` only see the CURRENT iface's direct objects; to address a nested widget you must (a) `inspect` the parent and find children with `kind="other"` + `object_type==1` (INTERFACE), (b) `inspect --interface-id N` on each, (c) `click --id N` (which routes through `FindWidgetByLabel`'s numeric path → global `world.GetObjectFromId`).
- `cli set_text --label <id>` / `cli select --label <id>` keep numeric label args as strings via `STRING_FLAGS_NO_SUBOP` (clients/cli/index.ts). Without that, Bun's parser turns "12345" into a JS number and silencer's `args["label"].get<std::string>()` throws `type_error 302` and aborts. Same pattern works for any future game-control op that takes a numeric label.
- `Interface::FindWidgetByLabel` (interface.cpp:781) interprets purely-numeric label strings as direct Uint16 global object ids — short-circuits to `world.GetObjectFromId`. So `cli click/set_text/select --label <ID>` (with the CLI string fix) bypasses the per-iface object scan and reaches widgets in any iface.
- The default game name from `nametextinput->SetText(Config::defaultgamename)` is `"New Game"` on a fresh HOME (set by the silencer's first idle Save). Subsequent runs preserve whatever was last typed. The Create button only bails when the textinput is literally empty.
- Dedicated server spawn works end-to-end from a tmp HOME — `services/lobby/proc.go` execs the same `silencer` binary with `-s 127.0.0.1 <port> <gameid> <accountid>`. The child inherits the env and finds assets via the parent binary's `CDResDir` resolution (macOS bundle Resources). Lobby log shows `[proc] spawned dedicated server` followed by `[hub] game N ready` once the child UDP-heartbeats back.
- gamecreate panel form: name input has uid=5 (GCRT_INPUT_NAME), password uid=6, security button uid=GCRT_BTN_SECURITY, map selectbox uid=4 (GCRT_SEL_MAP). Only the map needs explicit selection in capture — the rest have working defaults.
- After clicking Create on the gamecreate panel, the client shows an "Uploading map..." progress modal before transitioning to GameJoin. Watch for the "Choose Tech" button in a child interface to detect GameJoin (took ~5–10 s wall-clock in the test env; 200 × 0.1 s polls in capture.sh is safe).
- `Renderer::Rect` was promoted from private → public so the Clay bridge (and any future external dispatcher) can build dst rects for `Renderer::BlitSurface` without a friend declaration. It's just `{int w,h,x,y}` — nothing to encapsulate.
- Clay → Surface bridge entry point: `silencer::clay_bridge::Render(Game&, Surface*, Clay_RenderCommandArray)` in `clients/silencer/src/ui/clay/clay_bridge.{h,cpp}`. Conventions: `RECTANGLE`/`BORDER` color = `backgroundColor.r` as palette index (Uint8). `IMAGE` `imageData` = `PackImage(bank, idx)` (helper in clay_bridge.h, packs into `(bank<<16) | idx`). `TEXT` `fontId` = bank, `fontSize` = monospaced cell width, optional `userData` = `BankTextDrawData*` for brightness/colorRamp/alpha. `CUSTOM` `customData` = `ClayCustomData*` with a `CustomKind` enum (P5+ kinds added per primitive). Scissor maintained as a stack — see `g_clipStack` in clay_bridge.cpp.
- Clay determinism trap: without resetting `Clay_SetPointerState`/`Clay_UpdateScrollContainers`/`Clay_ResetMeasureTextCache` before each `Clay_BeginLayout`, two back-to-back layout passes in the same process produce different render-command geometry (~1.2% pixdiff). `EnsureInitialized` in clay_bridge.cpp does the resets unconditionally; downstream callers (P11+ screens) get this for free.
- Capture-PNG palette gotcha: `Game::GetPaletteColors()` is the LIVE dynamic palette and the main menu fades it in over ~15 frames (game.cpp:870). For deterministic Clay/UI shots, prefer the static base palette via `renderer.palette.GetColors()` (a non-const SDL_Color*; cast or accept). The smoke op (clay_smoke.cpp) uses the base palette.
- New include dir wired in CMake: `clients/silencer/src/ui/clay`. Bridge consumers can `#include "clay_bridge.h"` bare — same convention as the other UI subdirs.
- Custom CLI control op for the bridge smoke test: `cli clay_bridge_smoke --out <path>` (IMMEDIATE phase, registered in net/controldispatch.cpp). Calls `silencer::clay_bridge::RunSmoke` which builds a fixed 4-element tree and writes a 640x480 PNG. Repeatable test harness at `tests/lobby-clay/bridge_smoke/run.sh`.
- Clay primitives live at `clients/silencer/src/ui/clay/primitives/<name>.{h,cpp}` in `namespace silencer::ui::primitives`. They include `clay_bridge.h` for the BankTextDrawData/ClayCustomData ABI but NEVER `world.h`, `lobby.h`, `config.h`. Variants are explicit enums (no string variants). Per-frame userData payloads come from a fixed-capacity bump arena owned by the primitive TU; caller invokes `<Primitive>BeginFrame()` before `Clay_BeginLayout`. The `src/ui/clay` include dir is on the global include path, so primitives are reachable as `#include "primitives/<name>.h"` from anywhere.
- Adding a Clay-scene control op for a primitive unit test: 3 changes — declare `Run<Name>Test(Game&, const char*)` in clay_bridge.h, implement in `clients/silencer/src/ui/clay/<name>_test.cpp` (mirror clay_smoke.cpp: Surface(640,480,0), Render(game, &dst, cmds), CapturePNG with `renderer.palette.GetColors()`), and wire the op in net/controldispatch.cpp's HandleImmediate switch. New .cpp files require `cmake -B build -S clients/silencer` to refresh the GLOB_RECURSE source list (build errors with "undefined symbol" → reconfigure, then rebuild).
- The cli-agent harness (`tests/cli-agent/e2e/lib.sh`) auto-detects the binary at `clients/silencer/build/Silencer.app/...` first. In this worktree the canonical build sits at the worktree-root `build/`, so primitive test run.sh scripts must accept `SILENCER_BIN` overrides — set `SILENCER_BIN=$REPO/build/Silencer.app/Contents/MacOS/Silencer` when the worktree's `clients/silencer/build` is stale or missing. **The override must be set BEFORE sourcing lib.sh** — lib.sh checks `${SILENCER_BIN:-}` at source time and locks in the stale path otherwise.
- Clay 0.14 `Clay_OnHover` semantics: the registered proxy is invoked synchronously inside the NEXT `Clay_SetPointerState` call (not at EndLayout), reading the PREVIOUS frame's pointer state against the PREVIOUS frame's element hashmap. So a click input edge appears in the callback one frame after the input. Test timelines for "fires exactly once per press" must therefore measure clicks across the press transition + dispatch frames (≥2 down-frames), not within a single frame.
- CUSTOM render command pattern (P5 cookbook): allocate the payload from a per-frame arena BEFORE the CLAY block declaration so it can be referenced via `.custom.customData = ccd`. Then mutate the payload IN PLACE inside the block (after `Clay_Hovered()` etc.) — Clay captures the pointer value into the render command at EndLayout, so post-declaration mutations are visible to the bridge dispatcher. This lets a primitive set hover-dependent fields (e.g. brightness 128↔136) without two CLAY blocks.
- Bridge CUSTOM dispatch convention: `customData` always points to a `silencer::clay_bridge::ClayCustomData{kind, payload}` header; the bridge switches on `kind` and casts `payload` accordingly. New CustomKind values append to the enum in `clay_bridge.h` — bridge's `DispatchCustom` switch must have a case for each.
- `BankButton` (P5) variants: `Chrome` (B156x21 via CUSTOM payload, brightness 128↔136 on hover), `Inline` (BNONE — text-only via BankText BodySm, brightness shifts on hover), `Checkbox` (BCHECKBOX — IMAGE element with bank 7 idx 18/19 driven by `opts.selected`). All three use `CLAY_SID(label)` for stable runtime-keyed IDs; the label string is both the rendered text AND the Clay ID hash basis (labels must be unique within a layout). Per-frame bump arenas: `g_adapters` for click adapters, `g_chromePayloads`, `g_customData`. All reset by `BankButtonBeginFrame()`.
- For hover-state effect on bank-text inside a sprite-chrome button (Chrome variant), pass `brightness=136` to the inner `BankText` opt — matches legacy Button's effectbrightness applying to both the chrome sprite AND the rendered text (same Object effectbrightness member).
- `CLAY_SIZING_FIXED(<expr>)` triggers `-Wc++11-narrowing` when given an integer VARIABLE (Uint16, int). Int literals (156, 21) work because the compiler can prove the value fits. Hoist into a `const float w = static_cast<float>(...)` temp first; the macro double-evaluates its argument so cheap variables are better than function calls.
- `Toggle` (P6) primitive — CUSTOM-only (`CustomKind::ToggleSprite`, payload `{bank, index, effectColor, brightness}`). Brightness is resolved at primitive-call time from `selected ? opts.selectedBrightness : opts.unselectedBrightness`; bridge applies `EffectColor` (if != 0) then `EffectBrightness` (if != 128) on a per-call surface copy. Short-circuits both effect passes when effectColor=0 AND brightness=128 — zero copy/effect overhead for "boring" toggles. Per-frame bump arenas reset via `ToggleBeginFrame()`.
- Bridge CUSTOM payload convention: one POD struct per `CustomKind`. Don't reuse another primitive's payload even when fields overlap — kind-keyed dispatch makes divergent payload shapes free, and shared payloads would ripple changes across unrelated primitives.
- `Renderer::GetPixel`/`SetPixel` are declared `static inline` in `renderer.h` but DEFINED `inline` in `renderer.cpp` — they emit external symbols (`T __ZN8Renderer8GetPixelEP7Surfacejj`) so external TUs can call them, but the compiler will warn `-Wundefined-inline` at the call site. Warning is benign; the linker resolves them.
- `TextInput` (P9) primitive — CUSTOM-only (`CustomKind::TextInput`, payload `{text*, textLen, bank, fontWidth, effectColor, brightness, caretColor, caretHeight, showCaret}`). Bridge calls `Renderer::DrawText` then `DrawFilledRectangle` for the caret (1 px wide, height = `heightPx * 0.8`, y-offset -1 — matches legacy `Renderer::DrawTextInput` in renderer.cpp:1835). Primitive owns no state: caller pre-slices for horizontal scroll, pre-resolves `showCaret` (focus AND blink phase), pre-resolves `numbersOnly` filter screen-side. `inactive=true` overrides brightness to 64 and suppresses caret. `password=true` masks rendered chars to `'*'` via a per-frame slab of `char[256]` buffers (16 slots). `TextInputDispatchKey(handle, ch)` is a tiny screen-helper next to the primitive — '\n'/'\r' fires `onEnter` and returns true; other chars return false (caller appends to buffer via SDL_TEXTINPUT).
- Auto-scroll-on-append is SCREEN policy, not primitive state. Pattern: primitive takes immutable `scrollPosition` input; screen calls `ScrollTextBoxAutoScroll(prev, prevCount, newCount, lineHeight, height)` BEFORE/AFTER appending to compute "stay pinned to bottom" — returns `prevPos` unchanged if not at bottom previously, or `newMax` otherwise. Keeps the primitive stateless while preserving legacy `TextBox::AddLine(scroll=true)` behavior. Same approach generalizes to any append+follow pattern.
- Anchoring a visible block to the bottom of a Clay box (legacy `bottomtotop`): wrap the row column in an OUTER TOP_TO_BOTTOM container with fixed `(width, height)` AND `childAlignment = { CLAY_ALIGN_X_LEFT, CLAY_ALIGN_Y_BOTTOM }`; the INNER row column sizes to `CLAY_SIZING_FIXED(emit * lineHeight)`. Clay's alignment moves the inner column down by the leftover space. Works when the inner column underfits the outer (legacy under-fill case). When it overflows, Clay still draws the inner column at the bottom of the outer and overflows above — match the legacy unclipped overdraw behavior. No SCISSOR needed for the typical case.
- `CLAY_SIDI(label, index)` accepts a `uint32_t` index — use it to derive per-child stable IDs from a parent's dynamic ID (e.g. row IDs in a list). Avoid integer-promotion narrowing warnings by passing `static_cast<uint32_t>(i)` when `i` is `int`.
- Per-row click adapters: when each child element of a list needs to dispatch through `Clay_OnHover` with a row index, allocate one `RowAdapter{fn, user, index}` per row from a per-frame bump arena (`kAdapterCapacity = 1024` covers a 30-item list comfortably). The proxy reinterprets the captured `intptr_t` back to `RowAdapter*` and forwards `(user, index)` to the user's callback.
- Bridge ScrollBar dispatch ports `renderer.cpp:858-933` 3-slice track + thumb rendering into the `CustomKind::ScrollBar` branch. Uses `Renderer::GetPixel`/`SetPixel` for per-pixel track tiling (preserves transparent palette idx 0); thumb is `BlitSurface`d (no per-pixel work). Per-pixel writes are NOT routed through `ClipDrawRect` — instead they consult the active clip rect inline (`inClip` lambda) so per-pixel clipping is correct even with `SCISSOR_START` open. `BlitSurface`'s own clamp covers the thumb path.
- Composition primitives don't always need an emit function — `FormBorder()` is a header-only inline returning `Clay_BorderElementConfig{ .color = {220,0,0,255}, .width = {1,1,1,1,0} }`. Callers drop it into `.border = FormBorder()` on any CLAY block. This pattern (helper returning a config struct) is cleaner than wrapping with a callback when the primitive's job is purely "supply a style fragment". Use it for any future palette/stroke/sizing presets.
- A panel/container primitive can paint its background sprite via `.image = PackImage(bank, idx)` on the same CLAY element that has children — Clay's IMAGE render command for the parent fires before children render, so children overlay the chrome. No `.floating` gymnastics needed. The image blit at the bbox top-left uses the sprite's natural size, so size the parent CLAY block to match the sprite's dimensions (legacy bank 7 idx 8 = 222 × 390).
- `Clay_String` default-construct in a designated initializer is `{ false, 0, nullptr }` (isStaticallyAllocated, length, chars). Use it as the "no value" sentinel for optional `Clay_String` opts fields, then test `opts.field.length > 0` at call time.
- `Screen::Draw(ctx, dst, frametime)` virtual (default no-op) is the render-phase hook for Clay-driven screens. Called from `Game::Run()` between `screenbuffer.Clear(0)` and `renderer.Draw(...)`, iterating from the topmost non-overlay screen upward (matches `TickActiveScreen`). Order: Clay paint → world walk. So Clay-painted backgrounds/chrome land FIRST and world-object panels overlay correctly. Tick still owns input/state; only the rendering pass lives in Draw.
- The pix-diff baselines at `tests/lobby-clay/baselines/*.png` are **NOT pixel-deterministic across runs** — the lobby's panels (agency icons, chat indicators) animate at frame-tick rates and the lobby login flow takes a non-deterministic number of game ticks. Legacy-vs-legacy floor: ~27% byte diff. Any full-frame pixdiff against these baselines will see floor noise far above the prd's <1.0%-<5.0% thresholds. P11+ panel migrations should either crop diff to the panel bbox, freeze tickcount, or accept wider thresholds.
- For Clay primitives that wrap a sprite (background, chrome buttons), pre-subtract the sprite's anchor offset (`world.resources.spriteoffsetx/y[bank][index]`) from the floating `.offset` to land at the same pixels as the legacy renderer's overlay/sprite path (which subtracts the anchor before blitting). Bank 7 idx 1 (lobby bg) + idx 24 (B156x21 button) both have anchor (0, 0), but later sprites (e.g. bank 7 idx 8 right-chrome at (-403, -87)) have nonzero anchors.
- `LobbyClayScreen` inherits from `LobbyScreen` (rather than `Screen` directly) so the legacy CharacterPanel / ChatPanel / GameSelectPanel etc. can keep their `LobbyScreen &` owner refs and the ShowGame* swap helpers without modification. The base class API change required: `SetMapNameOverlay` virtual + panel pointer members private→protected. After P12-P17 finish migrating the panels to Clay, this inheritance can be deleted and LobbyClayScreen rebased on Screen.
- `SILENCER_LOBBY_CLAY=1` env var (read in `Game::GoToState(LOBBY)`) opts into `LobbyClayScreen`; absent or "0" pushes legacy `LobbyScreen`. Pattern reusable for any future Clay-vs-legacy A/B migration: `getenv(...) && [0] && [0] != '0'` keeps the compile-time path clean and makes opt-in a single env-var prefix.

- `tools/pixdiff/pixdiff --crop x,y,w,h <a.png> <b.png>` compares only the named rect (top-left origin). Out-of-bounds → 100.0. Use for per-region diffs without re-saving cropped baselines.
- `tests/lobby-clay/baselines/*.png` are captured at non-deterministic palette-fade phases — full-frame RGBA pixdiff against them shows ~17-27% diff regardless of implementation (legacy-vs-self capture floor is ~25% in the chrome strip). Verification needs a different shape (see P11 retry entry: option 2 / fresh-legacy comparison is recommended).
- Headless `Game::Loop` is wall-clock-gated; Loop time depends on the screen's render cost (legacy: 5 Overlay world-objects; Clay: one layout pass). The same `wait_frames=N` therefore elapses in different wall-clock durations across implementations, leaving sim-tick counters (e.g. `fade_i`) at different values. Drive tests off the milestone, not Loop count.
- `cli step --frames N` (controldispatch.cpp:656) advances the sim by EXACTLY N catch-up ticks and re-pauses. Sim-tick-deterministic — does NOT depend on the screen's render cost. Use this (not `wait_frames`) whenever a test needs both legacy and Clay paths to land at the same fade_i / same tick-driven animation phase. Paired with chrome-strip cropping, drops legacy-vs-Clay chrome diff from ~17% (wall-clock-gated) to ~0.2%.
- Cross-implementation pixel verification pattern (P11): boot the SAME lobby instance twice — once with legacy client, once with `SILENCER_LOBBY_CLAY=1` — drive both to LOBBY with the same milestone-based wait + a `step --frames 30` sim advance, then pixdiff the two screenshots. Faithful to the design doc's "<5% before/after" intent without depending on a frozen baseline PNG. Committed baselines stay as informational artifacts only.
- `lobby/panels/` and `lobby_clay/` are both on the silencer include path; bare `#include "character_panel.h"` is ambiguous. Clay panel migrations must use a `clay_` filename prefix (e.g. `clay_character_panel.h`).
- A Clay-migrated panel can simply SKIP its legacy `panel.Build(ctx, lobbyiface)` call in `LobbyClayScreen::Build`. The inherited legacy panel member's `interfaceId` stays 0, so its `Tick` (invoked via `LobbyScreen::Tick`) early-returns harmlessly. No Tick override needed for P12-P17.
- Per-row click adapters for a Clay panel with a small fixed row count (≤16) are simpler as a file-scope `Adapter[N]` array overwritten in place each frame than a `*BeginFrame()` arena. Arena pattern only pays off for variable/large row counts.
- For a Clay panel with a vector<{std::string,…}> line model that ScrollTextBox needs to render: allocate a file-scope `ScrollTextBoxLine slab[N]` and fill it inside Build from the live std::strings (`.text = c_str()`). std::string c_str() is pointer-stable across the Build call (no mutations during layout), so the slab can point into the std::strings without copying. Reusable for any append-style line model (chat, notifications, mission log).
- Background-sprite positioning for any panel that wraps a single legacy `Overlay` bg sprite with default x=y=0: emit one CLAY block sized to `(spritewidth, spriteheight)`, `.image = PackImage(bank, idx)`, `.floating.offset = (-spriteoffsetx, -spriteoffsety)`. The Clay bridge blits at the bbox top-left; pre-subtracting the anchor lands at the same pixels as legacy's `obj_x - spriteoffsetx`. One draw command, byte-identical.
- Auto-scroll-on-append using `ScrollTextBoxAutoScroll`: capture prevCount BEFORE the push, push, capture newCount AFTER, then `scrollPos = ScrollTextBoxAutoScroll(scrollPos, prevCount, newCount, lh, h)`. Doing this per-push (not once at end of drain) keeps "stay pinned to bottom" correct when multiple lines arrive in one drain.
- Legacy `game_select_panel.cpp` has INVERTED enum names: uid `GSEL_OVL_INFO` (3) at y=382 actually holds the SECURITY text; uid `GSEL_OVL_LIMITS` (5) at y=406 holds the MinLv/MaxLv LIMITS text. Follow the y-coord positioning, not the enum names — the Clay reimplementation's row order top-to-bottom is (name, map, security, creator, limits).
- Clay-mode override of a legacy ShowGame* swap helper: (1) make the base method virtual in LobbyScreen.h, (2) override in LobbyClayScreen to tear down the OTHER legacy right-side panels without rebuilding the Clay one (inline a 4-line TearDownRightPanels equivalent — the file-static helper in lobby_screen.cpp isn't reachable from the Clay TU), (3) flip `world.lobby.gamesprocessed = false` so the next Tick re-snapshots the games list (mirrors what the legacy `gameSelect->Build`'s SelectBox first-pass walk used to do).
- Mutex-gating Clay panel rendering when a legacy right-side panel is alive uses `!gameCreate && !gameJoin && !gameTech` in BOTH Tick AND Draw. Keeps the Clay tree invisible while a legacy panel owns the right column, and prevents Clay onClick adapters from firing (no Clay element → no Clay_OnHover registration). After P15-P17 migrate the rest, the gate becomes a state-enum check instead of three pointer checks.
- For a Clay panel that snapshots a `world.lobby.games`-style list (any append/delete-driven model), the rebuild trigger is the same `!world.lobby.gamesprocessed` flag the legacy SelectBox first-pass used. After rebuild set `gamesprocessed = true`. Track selection across rebuilds by SELECTED OBJECT ID (e.g. gameid), not row index — on rebuild, search the new row vector for the previous selected id and restore the index.
- A ~1% Clay-vs-legacy diff floor exists for any panel that emits a `ScrollList` with `showScrollbar=true`. The scrollbar render path uses `Renderer::GetPixel`/`SetPixel` per-pixel track tiling whose exact output diverges slightly from legacy `ScrollBar::Draw`. P8 (ScrollTextBox) hid this with `showScrollbar=false`. P14 (GameSelectPanel) is the first surface where it actually renders. Expect ~1% for any future panel that exposes a scrollbar.
- `ScrollList` (P7) auto-suppresses the scrollbar when itemCount ≤ visibleLines (mirrors legacy `scrollbar->draw = overflow?`). No API change — list w/ scrollMax=0 just doesn't emit the scrollbar CLAY block, and the rows column reclaims the scrollbar's pixels. After this fix P14's pixdiff dropped 1.14% → 0.149%.
- Friend privilege in C++ is NOT inherited. `LobbyClayScreen` (derived from `LobbyScreen`, which is friended in world.h) needs its own `friend class LobbyClayScreen` in world.h to access World's private members. Same trap for any future Clay screen that derives from a friended base.
- New CLI op `cli lobby_show_panel --panel select|create|join|tech` drives `LobbyScreen::ShowGame*` (virtual) directly. Reusable for any lobby-right-pane test where the Clay path has no world Interface objects to address via `cli click`. Adds `Game::GetScreenContext()` accessor.
- Tests that open GameCreatePanel MUST pin `Config::mapapiurl` to either an unreachable URL or the test lobby's local map-api — silencer's default `mapapiurl=https://admin.arsiamons.com` is a real production endpoint whose `FetchServerMapList` response ordering is not stable across consecutive HTTP calls. See `tests/lobby-clay/game_create_panel_test/run.sh`'s `write_config` helper for the pattern (writes `~/Library/Application Support/Silencer/config.cfg` with `mapapiurl=http://127.0.0.1:$MAP_API_PORT`).
- For row+right-badge legacy patterns (SelectBox's "[DL]" badge in the right margin of remote-map rows), do NOT add a flag to ScrollList. Strip the legacy "[DL] " prefix when filling the per-frame Clay_String slab and accept the missing-badge pixel gap (~16x11 per row). For future "row with right-side metadata", compose plain CLAY rows with a right column instead — ScrollList stays screen-agnostic.
